# QAS-02 검증 기록

## 구현 범위

- 입금 완료 거래의 운송장 등록과 취소를 상태·버전·소유자 조건의 원자적 UPDATE로 선점한다.
- 선점 커밋이 완료된 요청만 외부 Mock을 호출한다.
- 외부 성공이면 선점 상태와 버전을 다시 검사하고 최종 상태를 저장한다.
- 외부 실패·불명확·타임아웃이면 처리 중 상태를 유지하고 일반 요청의 재실행을 차단한다.
- API는 성공 200, 처리 중 202, 거래 충돌 409, 입력 오류 422, DB 오류 503을 반환한다.

## 자동 검증

2026-11-26, 실제 Supabase PostgreSQL과 은행·택배 Mock으로 실행했다.

| 검증 | 결과 |
| --- | --- |
| 새 거래마다 운송장 등록·취소를 동일 버전으로 경쟁, 총 100회 | 모든 회차에서 성공 1건·충돌 1건 |
| 외부 Mock 호출 | 거래당 1건 |
| DB 최종 상태·운송장 번호와 Mock 처리 종류 비교 | 불일치 0건 |
| 운송장·환불 각각의 성공 경로 | 통과 |
| 외부 실패·불명확·타임아웃, 양쪽 작업의 재선점 차단 | 통과 |
| 요청자 권한·버전·허용 상태 검사 | 통과 |

최초 전체 실행은 DB 연결 중단 1건으로 실패했다. 충돌 방지 성공으로 집계하지 않았다.
재실행은 독립된 거래 4개씩 병렬 검증하여 서비스 테스트 5개가 모두 통과했다
(`Ran 5 tests in 123.762s`, `OK`). 각 거래 내부에는 서로 다른 DB 연결의 두 요청이 경쟁한다.

API 추가 후 실제 DB 성공·재요청 충돌을 포함한 API 테스트 7개가 통과했다.
2026-11-28에는 `/docs`에서 역할 헤더가 누락되는 문제를 수정했고,
OpenAPI에 필수 헤더와 역할 선택값이 노출되는 회귀 검사를 포함한 API 단위 테스트 7개가 통과했다.

## 수동 검증

- 로컬 HTTP API로 새 가상 거래에 운송장 등록 200 후 취소 409를 확인했다.
  최종 DB는 `WAYBILL_REGISTERED`, version 3이었다.
- 사용자가 Swagger UI에서 취소 성공 후 같은 거래의 운송장 등록 409를 확인했다.

## 재현과 제한

실행 명령과 로컬 데모 사용법은 `backend/README.md`를 참고한다.
테스트는 새 거래를 만들고 자신이 생성한 행만 정리한다.
수동 데모로 생성한 거래는 결과 확인을 위해 DB에 남는다.

100회 검증은 서비스 계층의 동시 호출이며 HTTP 부하 시험이나 실제 은행·택배 검증은 아니다.
데모의 역할 헤더는 인증이 아니다. 운영 앱은 인증/실제 Port 연결 전까지 요청을 차단한다.
자동 복구·작업 이력 영속화·외부 결과 조회는 QAS-03과의 후속 연동 범위다.
